# Contributing to Atom Bowl

Thanks for helping! Please read this before opening a pull request.

## The one rule: always open a pull request

**Never push directly to `main`.** All changes go through a pull request, with no exceptions. Direct pushes to `main` will get your account suspended from the project.

1. Fork the repo, or create a branch (`git switch -c fix/short-description`).
2. Make your change and commit it.
3. Open a pull request into `main` and describe what and why.
4. Wait for review. Maintainers merge.

## Setup

Use Node.js 22 or 24, then:

```bash
npm ci
npm run build
npm test
```

Preview locally with `npx firebase emulators:start --only hosting` and open http://localhost:5000.

## Where things live

- `src/ts`, `src/html`, `src/css`, `src/data`: sources. Edit these.
- `docs/`: the built site served by Firebase Hosting. It is generated by `npm run build` and committed, so include the rebuilt output in your PR. Do not hand-edit `docs/js`.
- `tests/`: `npm test` for unit tests, `npm run test:firebase` for Firestore rules (needs Java 21+).
- `firestore.rules`: security rules. Changes need extra review.

## Guidelines

- Keep the stack simple: no frameworks, no backend. Logic belongs in TypeScript.
- Match the surrounding code style.
- Add or update tests for behavior changes.
- Run `npm run build` and `npm test` before opening the PR.
- Keep PRs small and focused.
- Never commit secrets or provider keys. The public Firebase web config is the only exception.
- Do not add dependencies without discussing them in an issue first.
- Question data: only submit questions you have the right to share, and keep the existing JSON format.

## Reporting bugs and ideas

Open an [issue](https://github.com/shankar-sachin/atombowl/issues). For bugs, include steps to reproduce, your browser, and screenshots if useful. **Security problems** follow [SECURITY.md](SECURITY.md).
